# MEGA-X Gate 1 — Online Core + Arena Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the hosted MEGA-X online Arena to the recovered offline visual/interaction baseline, remove avoidable client-side lag, restore high-resolution cards and motion, and add a backend-authoritative active-turn timer without weakening server authority.

**Architecture:** The recovered offline App/CSS remains the presentation baseline. The browser gives immediate safe visual feedback but never decides gameplay outcomes. Match state, action legality, deadlines, timeout consequences, reconnect handling, and results remain authoritative in Supabase/`match-action`; the client renders server timestamps and state transitions.

**Tech Stack:** React 19, TypeScript 5.9, Vite 7, Node verification scripts, Supabase PostgreSQL + Edge Function, Vercel production deployment.

**Spec:** `docs/superpowers/specs/2026-08-29-mega-x-finish-design.md`

## Global Constraints

- Browser remains presentation/input only; backend remains authoritative for gameplay outcomes.
- No client-only gameplay timer that can be bypassed.
- Existing MEGA-X rules, terminology, coin-toss flow, card data, and visual identity are not redesigned.
- Mobile-first browser support is mandatory.
- The recovered offline build is the Arena visual/interaction baseline.
- No declaration that Gate 1 is complete until the hosted production flow is verified.
- Work directly on `main`; do not create a feature branch.
